# ПЕРЕДАЧА ПРОЕКТА: перенос заданий курса ЕГЭ на gsvv.ru/inf/ege/

Этот файл — стартовая точка для нового чата/агента (Opus 5.5 и любой другой).
Здесь описано: что за проект, где что лежит, откуда берутся задания,
как устроен формат курса, как собрать и выложить, и какие ограничения уже
известны. Правила оформления заданий здесь нарочно не описаны — их задаёт
пользователь по ходу работы.

Проект: сайт репетитора по информатике, курсы для ЕГЭ/ОГЭ.
Репозиторий: `hardit654-hub/inf-site`, ветка **`main`**.
Живой сайт курса: <https://gsvv.ru/inf/ege/>

## 1. Главное в двух словах

0. **Ответы и прогресс учеников трогать нельзя ни при каких обстоятельствах.** Это живые
   люди: сломанный ключ шага — это стёртые ответы, которые не вернуть. Перед любой
   правкой `course.js` читайте §5. Остальное в проекте можно переделать — прогресс нельзя.

1. Источник заданий — **курс на Stepik** (недоступен из поиска, id 125485). Пользователь
   присылает ссылку на раздел, например
   `https://stepik.org/lesson/890678/step/1?unit=1420692` — это вход в раздел «№ 1 Теория графов».
2. Задания переносятся **дословно**: текст, разметка, порядок шагов и уроков сохраняются.
   Формулировки не переписываются.
3. Картинки (графы, таблицы дорог, таблицы истинности) **берутся как изображения со Stepik**
   и кладутся в репозиторий. **Не перерисовывать их самому** — пользователь это прямо запретил.
4. Ответы в API Stepik закрыты. Их берут из файлов ответов, которые уже лежат в репозитории
   (`src/<раздел>/answers*.py`). Если ответа нет — задачу решать самому и записать.
5. Сборка: `python3 build.py` → `site/`. Пуш в `main` → GitHub Actions выкладывает по FTP.

## 3. Хостинг: что и куда загружается

- Домен **gsvv.ru**, FTP-пользователь `u3640031_deploy`, его домашняя папка —
  `www/gsvv.ru/inf`. По FTP локальная папка `site/` кладётся в `./inf/` на сервере.
  Значит: `site/ege/index.html` → <https://gsvv.ru/inf/ege/index.html>.
- **Выкладывает только CI** (`.github/workflows/deploy.yml`), по пушу в `main`.
  Секреты в GitHub: `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, `DB_*`.
- Рабочий процесс запускается **не на каждый пуш**, а только если в коммите менялись
  `site/**`, `src/**`, `build.py` или сам `deploy.yml` (см. `paths:` в начале файла).
  Пуш, где тронут только `AGENTS.md`/`README.md`, сайт не пересоберёт — это нормально.
- Ручной запуск: вкладка **Actions → «Загрузка сайта на хостинг» → Run workflow**.
- Кроме `site/`, тот же workflow кладёт на сервер ещё две вещи из репозитория:
  `site/forms/` → `gsvv.ru/forms/` (страница записи на поездку) и
  `deploy-vdk-restore/root/`, `deploy-vdk-link/` → корень домена (ВДК, см. ниже).
- В конце workflow отдельным шагом проверяется, что PHP на хостинге работает, и только
  тогда загружается `config.php` с паролем базы (иначе файл с паролем отдавался бы как текст).
  Если в логе `::warning::PHP на хостинге не выполняется` — личный кабинет не заработает.
- В корне домена (`gsvv.ru/`, не `/inf`) живёт **ВДК** — ведомость дисциплинарного
  контроля. Это не часть курса, но папки `deploy-vdk-restore/` и `deploy-vdk-link/`
  восстанавливают её при каждой выгрузке. **Не удалять и не переименовывать.**
- На хостинге также может лежать то, чего нет в репозитории (например `kr1.html`).
  FTP-выгрузка не удаляет лишнее — не «чистите» сервер.

## 4. Формат `course.js` (узловой момент)

`src/<раздел>/course.js` — это JavaScript-файл с одним объектом:

```js
window.COURSE = { "id": "ege-inf", "num": 1, "section": { … } };
```

Внутри `section`:

```jsonc
{
  "num": 1,                                            // номер задания ЕГЭ (ключ прогресса, НЕ менять у существующих)
  "title": "№ 1 Графы, таблицы дорог",
  "lessons": [
    {
      "num": 1,                       // номер урока в разделе
      "title": "Теория графов",
      "steps": [ /* шаги по порядку */ ]
    }
  ]
}
```

### Типы шагов

| `type`  | Что это | Поля |
|---------|---------|------|
| `text`  | теория, разборы, примеры | `blocks` |
| `video` | заглушка под видео (пользователь вставит своё позже) | `title` |
| `fill`  | задача с полями ввода | `blocks`, `fields`, `answer` |
| `choice`| тест с вариантами | `options`, `answer` (+ `multi: true`) |
| `match` | сопоставление списков | `items`, `options`, `answer` |

### Блоки (`blocks`) — из чего состоит текст шага

```jsonc
"blocks": [
  { "t": "html",    "v": "<p>…</p>" },          // разметка как есть
  { "t": "code",    "v": "print(1)" },          // блок кода (моноширинный)
  { "t": "details", "title": "Решение", "v": [ /* вложенные блоки */ ] }  // раскрывающийся разбор
]
```

### Поля ответа `fill`

```jsonc
"fields":  [ { "label": "Ответ", "n": 1 }, { "label": "x1", "n": 3 } ],
"answer":  [ ["56"], ["1", "0", "1"] ]        // по полям и по значениям внутри поля
```

- `n` — сколько ячеек ввода в одном поле. Для одной строки ответа — `n: 1`.
- Строка-ответ с `||` — варианты: `"8||08"` (засчитается любой).
- `txt: true` у поля делает ввод текстовым вместо числового.

### Ответ на матрицу (таблица смежности) — сейчас так

В разделе № 1 матрица смежности (шаг 1.5) задана **одной строкой**:
`"0 11 13 0 0 0 0; 11 0 0 14 0 0 0; …"`, а на сайте это один длинный ввод.
Пользователь хочет **таблицу из отдельных ячеек**. В движке готового решения нет —
нужно либо расширить `engine.html` (`fillHTML`), либо задать матрицу множеством
полей: строка матрицы = поле с `n` = размерности. Второй путь возможен без правки
движка, проверить на одном шаге и показать пользователю.

### Ключи прогресса

`build.py` собирает все разделы в одну страницу, ключ прогресса —
`course-<id>-s<num>` (например `course-ege-inf-s1`). У существующих разделов
`num` менять нельзя — потеряются ответы учеников.

## 5. Прогресс учеников: как он хранится и как его не убить

**Это самое важное правило проекта.** В курсе учатся живые люди, их ответы — не тестовые
данные, восстановить их будет нечем. Всё остальное можно переделать, прогресс нельзя.

### Где он живёт

Две копии, которые движок сливает между собой (`mergeState` в `engine.html`):

| Где | Ключ | Кто пишет |
|---|---|---|
| `localStorage` браузера | `course-<id>-s<num>` (значение — `{pos, st}`) | движок, сразу при вводе |
| база на хостинге, таблица `inf_progress` | `user_id` + `ckey` = тот же ключ | `site/api/index.php`, `progress_put` |

Внутри `st` запись на каждый шаг: `sid = <номер урока>/<ключ шага>`, например `2.1/7`.
В записи: `v` (что ввёл ученик), `last`, `att` (число попыток), `ok`, `rev` (смотрел ответ).
Позиция в курсе — отдельным ключом `pos-ege-inf-all`.

### Что рвёт прогресс (проверено по коду)

1. **`sid` = `<номер урока>/<ключ шага>`.** Номер шага — это **порядковый номер среди
   шагов без своего `key`**, а не позиция в массиве. Значит:
   - вставили шаг в **середину** урока → у всех следующих шагов сдвинулся номер → их
     ответы «переехали» на соседние задачи. Даже просто **удалить** шаг с проверяемым
     ответом нельзя — тот, что был после, унаследует чужой `ok`.
   - поставить в середину теоретический шаг (`text`/`video`) всё равно плохо: это сдвиг
     позиции, а поломка может вылезти позже.
   - **Безопасно** только добавлять в конец урока. Всё, что вставляется в середину или
     переставляется, обязано получить **явный `"key"`** (`"key": "t12"` — любая строка,
     только не число и не совпадающая с другой). Движок и `build.py` (`keys()`) такие
     ключи уже понимают.
2. **`section.num`** — это имя ключа в `localStorage` и `ckey` в базе. Изменение
   **любого** раздела: ключи сдвинутся у всех сразу. Не менять никогда.
3. **Номер урока** (`lessons[].num`) входит в `sid`. В двух разделах уроки занумерованы
   `2.1 … 2.7`, потому что раздел 1 исторически сгенерирован из второго. **Номера
   уроков не переименовывать и не перенумеровывать** — только добавлять урок с новым
   номером в конец.
4. **Порядок уроков и позиция раздела в `ORDER`** (`build.py`): ни уроки внутри раздела,
   ни разделы между собой не переставлять.
5. **«Сбросить прогресс», «Начать заново», кнопка «Показать ответ»** — это пути
   ученика. Не трогать их логику. «Начать заново» сознательно оставляет монетки
   (на сервере каждая задача оплачивается один раз навсегда).
6. **`merge_state` в PHP** сливает записи: `ok` и `rev` не сбрасываются, `att`
   берётся по максимуму. Если переписываете слияние — только в сторону
   «ничего не терять».
7. **`reset: true`** стирает раздел на сервере. Ставить его можно, только если сам
   ученик нажал «Сбросить прогресс». Больше нигде.

### Обязательно проверить после любой правки `course.js`

```bash
git diff src/<раздел>/course.js     # в diff не должно быть: удалённых шагов,
                                    # сдвинутых номеров, пропавших "key"
```

Перед пушем ответить самому себе на три вопроса:

1. Не изменилось ли число шагов в каждом уроке? (кроме добавлений в самый конец)
2. Не поменялись ли `section.num` и `lessons[].num`?
3. У всех шагов, вставленных в середину, есть `key`?

Если хотя бы один ответ не «да» — правку делать нельзя без явного разрешения пользователя.

### Что делать, если прогресс всё-таки пострадал

1. **Не пушить дальше.** Сначала откатить `course.js` к последнему рабочему коммиту
   (`git checkout <sha> -- src/<раздел>/course.js`) — пока испорченное состояние не уехало.
2. Посмотреть, что именно поменялось: `git diff <sha>..HEAD -- src/<раздел>/course.js`.
3. Данные в базе — таблица `inf_progress`, `localStorage` — восстанавливаются только
   если есть текст ответов; база на хостинге не бэкапится автоматически.

### ⚠ `num` — это НЕ номер задания ЕГЭ

Исторически `num` раздавался по порядку подключения раздела, поэтому номера
не совпадают с названием папки. Действующая таблица (проверено по `course.js`):

## 6. Откуда берутся задания (Stepik)

### Шаги в терминах API

Цепочка: **раздел → unit → урок → step**. `lesson.steps` — это список **unit id**,
а не step id. Далее `units?ids[]=…` даёт `lesson` для каждого unit, и уже
`lessons?ids[]=…` даёт массив **step id**. Только потом `steps?ids[]=…` отдаёт шаги.

### Выгрузка

Формат готовой выгрузки — `sources/2-logika/steps_all.json`:

```jsonc
{
  "meta":    { "section": 439737, "course": 125485, "title": "✅ № 2 Логика" },
  "units":   { "1": { "unit": 1420756, "lesson": 1037604, "title": null }, … },
  "lessons": { "1037604": { "id": 1037604, "title": "Решение в Python Ⅰ", "steps": [4283037, …] }, … },
  "steps":   { "4283037": { "id": …, "lesson": …, "position": 1, "status": "ready",
                            "block": { "name": "string", "text": "<p>…HTML шага…</p>" } }, … }
}
```

`block.name` бывает: `text`, `string`, `number`, `table`, `matching`, `choice`, `video`.
Шаги `video` отбрасываются.

### Картинки

Ссылки в HTML выглядят так: `<img src="https://ucarecdn.stepik.net/<uuid>/">`.
Скачать прямо со Stepik (CDN отдаёт файлы без авторизации), а имя файла своё:
`sources/<раздел>/img<раздел>.<урок>.<шаг>-<n>.png`.
Список «имя + URL» кладётся в `sources/<раздел>-urls.txt`, и `fetch.yml`
скачивает его автоматически при пуше (уже пропущенные файлы не трогает).
Пример готового списка — `sources/2-urls.txt`.

### Ограничения Stepik (проверено опытом)

- API отдаёт шаги только при живой сессии в браузере; `curl` без неё получает
  заглушку/бот-защиту. Через браузер (`fetch` в консоли) — работает.
- Ответы (`number`/`table`/`matching`) в API **закрыты** (403/404). Не пытаться достать.
- Шаги решают прохождением задания в браузере и чтением результата, либо решением самому.
- **Не вставлять** в сайт `stepik`, `ucarecdn`, `PRO100`, `rutube`, `youtube` в видимом
  тексте и URL. `build.py` сам вычищает водяной знак «PRO100 ЕГЭ информатика ЕГЭ»,
  абзацы про `stepik.org` и ссылки на PRO100 (функция `scrub()`), но остальное руками
  не протаскивать.
  Проверка собранной страницы (должно быть пусто):
  `grep -o -i 'stepik\|ucarecdn\|pro100' site/ege/index.html`
  Её пока проходят все разделы.

  А вот ссылки на rutube/youtube `scrub()` **не** убирает: в готовой `site/ege/index.html`

## 7. Как собирается сайт

```
python3 build.py
```

Что делает `build.py`:

1. Читает `src/<курс>/course.js` (со всех курсов в списке `COURSES` и `ORDER`).
2. `scrub()` — вычищает следы Stepik/площадок из текстов.
3. `rebase()` — переписывает относительные ссылки под адрес курса (`../ege/…`).
4. Склеивает все разделы в один `window.COURSE` и вставляет в `src/engine.html`.
5. Пишет `site/ege/index.html`, старые адреса-редиректы `site/ege-N/`, `site/inf7/`, `site/oge/`.
6. Копирует картинки из `sources/<раздел>/` в `site/ege/img/` под чистым именем.
7. Пишет `site/kabinet/courses.json` — список уроков для выбора домашки.

Важно: **сборщики отдельных разделов (`src/<n>/build*.py`) вызываются вручную**, а не
`build.py`. `build.py` только пересобирает страницы из уже готовых `course.js`.
Порядок для нового раздела:

```
python3 src/<n>/build<n>.py      # course.js + что нужно по мелочи
python3 build.py                 # site/
git add -A && git commit -m "…" && git push   # CI выложит
```

Отдельно про CI: `deploy.yml` при пуше в `main` **тоже запускает `python3 build.py`**
и коммитит результат от имени бота («Сборка страниц курсов»). Поэтому собранный `site/`
приезжает в репозиторий двумя путями — от вас и от бота. Не удивляйтесь лишнему коммиту
`github-actions[bot]` после пуша: это нормально.

Ветку `main` может двигать бот, поэтому перед пушем делайте `git pull --rebase origin main`.

Если `course.js` для какого-то раздела лежит сжатым (`src/<n>/course.js.xz.b64`), CI
распаковывает его сам и удаляет `.b64`. Обычно же лежит готовый `course.js`.

### Предупреждение по разделу № 1

`src/1/build1.py` тянет данные из `sources/2/steps_all.json` и **раздел 1 сгенерирован
из раздела 2** — так исторически сложилось. Кроме того, он рисует часть графов
через `pics.py`/`pics_kege.py` (SVG). Пользователь эти перерисовки не принял:
«не отрисовывай сам граф, иначе это некрасиво получается и долго».
Если берётесь за раздел № 1 — сначала переписать `build1.py` на свою выгрузку
(как `build2.py`), картинки брать исходные со Stepik.
Текущее решение пользователя: **раздел № 1 пока оставлен как есть.**

## 8. Проверка перед пушем

1. **Сверить прогресс (§5)** — до всего остального:
   ```bash
   git diff origin/main -- src/*/course.js | head -200   # нет удалённых шагов и "key"
   python3 - <<'PY'
   import json,subprocess
   def L(t):
       d=json.loads(t[t.index('{'):t.rindex('}')+1])
       return d.get('section') or d.get('sections',[None])[0]
   for p in subprocess.check_output(['git','ls-files','src/*/course.js'],text=True).split():
       try: new=L(open(p).read())
       except Exception as e: print('ПРОПУСК',p,type(e).__name__); continue
       try: old=L(subprocess.check_output(['git','show','origin/main:'+p],text=True,stderr=subprocess.DEVNULL))
       except Exception: continue
       same=(new['num']==old['num'] and [l['num'] for l in new['lessons']]==[l['num'] for l in old['lessons']]
             and [len(l['steps']) for l in new['lessons']]==[len(l['steps']) for l in old['lessons']])
       if not same: print('ПРОВЕРИТЬ', p, 'num', old['num'], '->', new['num'],
                          [(o['num'], len(o['steps']), '->', n['num'], len(n['steps'])) for o,n in zip(old['lessons'],new['lessons']) if o['num']!=n['num'] or len(o['steps'])!=len(n['steps'])])
   print('сверка закончена')
   PY
   ```
   Скрипт печатает только разделы, где поменялись `num`, номера уроков или число шагов.
   Каждая такая строка — повод остановиться и разобраться.
2. Ответы: в разделе 2 есть проверка таблиц
   `python3 src/2/tables2.py && python3 src/2/check2.py`.
3. Локально открыть собранную страницу и пройти раздел: поля ввода на месте,
   картинки видны, теоретические шаги без полей ответа.
4. В браузере всегда открывать со случайным параметром (`?rand=…`), иначе старый
   ответ и старая версия страницы берутся из localStorage/кэша.
5. После пуша CI идёт ~2–3 минуты:
   `gh run list`, `gh run view <id>`.
6. Проверить живую страницу `https://gsvv.ru/inf/ege/?s=<номер>#<урок>.<шаг>`.
   И там же убедиться, что старый ответ ученика на месте (войти или посмотреть
   локально, где уже есть прогресс).

> Внимание про `?s=`: это **ключ прогресса из таблицы §4**, а не номер задания ЕГЭ.
> Для `src/12` страница откроется как `?s=42`, а не `?s=12`.

Нюанс: `build.py` **не** пересоздаёт `site/` с нуля — он дописывает и обновляет файлы
(перезаписывает идентичные не трогает), поэтому старые редиректы и лишние файлы в `site/`
остаются. Смотреть собранное локально: `file://…/site/ege/index.html?rand=1`.

## 9. Что нельзя делать

- **Трогать прогресс учеников** (см. §5): менять `section.num`, номера уроков, порядок
  уроков и шагов, вставлять или удалять шаги в середине урока без явного `key`,
  править «Сбросить прогресс» / `reset` / слияние прогресса.
- Менять формулировки заданий и раскладку шагов относительно Stepik.
- Отрисовывать графы/таблицы самому вместо исходных картинок.
- Ставить вместо видео-шага чужие разборы ссылками на ролики: видео у пользователя своё.
- Писать в видимый текст ссылки на Stepik, PRO100, rutube, youtube.
- Удалять `deploy-vdk-*/` — это соседние страницы в корне домена.
- Менять `num` существующего раздела (сломает сохранённые ответы учеников).
- Удалять/переименовывать папки разделов в `site/ege-N/`: там редиректы на `../ege/?s=N`.

## 10. Плейбук для нового раздела (пошагово)

1. Пользователь присылает ссылку на раздел Stepik (URL содержит `unit=…`).
2. Собрать карту: раздел → units → lessons → step id (см. §6).
3. Выгрузить шаги в `sources/<номер>-raw/` или `sources/<номер>/steps_all.json`.
4. Выписать картинки в `sources/<номер>-urls.txt`, скачать в `sources/<номер>/`.
5. Взять ответы из `src/<номер>/answers*.py`; чего нет — решить и дописать.
6. Написать/поправить `src/<номер>/build<n>.py` по образцу `src/2/build2.py`.
7. `python3 build.py`, сверить раздел в браузере.
8. Коммит + пуш, дождаться CI, проверить живую страницу.
